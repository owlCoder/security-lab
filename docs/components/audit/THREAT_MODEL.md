**Original assessment (S-04):** Vanja Jovanov (Team 12, member 7), PR #76
**Update to the current state (S-18):** Bogdan Pećanac (Team 12, member 1)

**Status:** documents the inspected code at that commit. Planned controls and integrations are explicitly marked; this is not a production-readiness claim.

## Scope and security objective

AUD-01 records security-relevant events with trustworthy actor, event, time and outcome fields. AUD-06 is intended to let an authorized teacher inspect only permitted events for a course. The audit record is security evidence, not a diagnostic log, an attempt history or laboratory content.

The assessment covers the Audit contract, domain, writer, PostgreSQL store, correlation middleware, course read policy and query service, host composition and the integration points with Access, Identity, Review and Administration. At the assessed commit the writer is registered in the running API (`AddAudit(configuration)`) and is used by Identity (login, logout, throttled login, account status), by the Access denial forwarder, by revision review and by the administration relay. It does not claim that an AUD-06 endpoint is available: the policy and the query exist, but no route exposes them. It does not cover deployment: the runtime role and the connection strings must be provisioned by the operator. Current facts and residual work are in [INTEGRATION.md](INTEGRATION.md), [PERSISTENCE.md](PERSISTENCE.md), [S16-RUNTIME-TRANSACTIONS.md](S16-RUNTIME-TRANSACTIONS.md) and the DFD ([source](diagrams/audit-dfd.mmd), [rendered](diagrams/audit-dfd.svg)).

## Assets and trust boundaries

| Asset | Security property |
|---|---|
| Audit events and schema | Integrity, provenance, append-only history (runtime privileges and a database trigger), bounded retention |
| Actor and course scope | Derived from trusted server-side identity and resource context; never inferred from client claims |
| Event details | Allowlisted, bounded, non-secret metadata only |
| Audit read results (future AUD-06) | Confidentiality by active per-course authorization and least disclosure |
| Correlation and event identifiers | Trace a request and deduplicate retries without granting authority |
| Database credentials and migrations | Runtime has minimum rights; schema changes use a separately controlled identity |

Trust boundaries (numbered as in the DFD):

1. Browser/client to API: request fields, route IDs, filters, headers and cookies are untrusted.
2. Inside the Platform.Api process: Identity, Access, membership, Review and Administration are separate modules with separate owners and talk through contracts. Their semantics require agreement. A provider outage is not an authorization grant.
3. Application to PostgreSQL: parameterized queries cross into a separate data boundary. Runtime permissions and the append-only trigger reduce impact but do not prove caller authorization.
4. Migration/bootstrap operator to database: privileged DDL and grants are separate from normal application writes.

Future, not exposed at this commit: audit data to the teacher UI. Course filtering and field minimization must happen server-side before selection, count, paging or serialization.

## Security status and acceptance conditions

At the assessed commit the write path is active end to end for the producers listed in the scope: login, logout and throttled login (Identity), Access denials, revision review and the administration relay write through the Audit module, and account status change, unlock and revision review commit together with their audit row. History is protected by the runtime role and by the append-only trigger. The correlation ID is generated per request. The course query and the course read policy exist and are tested at component level.

AUD-06 is not reachable: no route exposes the query, and the course endpoint and the `audit.events.viewed` event are not part of this commit. Do not mark AUD-06 implemented until positive and negative API tests demonstrate active membership or delegation checks, cross-course isolation, provider outage denial, current revocation, minimal fields and no leakage through counts or pagination.

Durable AUD-01 coverage is demonstrated only for the producers and paths named above. It is not demonstrated for other mutations, for denial audit under audit outage (best effort by design), for production database grants of each producer, or for retention, backup and restore.
